# 动画重生成计划（pose-first 管线）

> 流程（用户定稿）：参考图 →（EditPlus 生成动作关键帧）→（H3 fl2va 首尾帧驱动）→ 抽帧键控 → 桌宠帧序列
> 通用参数：768×768 ｜ short_edge 768 ｜ steps 30 ｜ 107帧/24fps（最短时长）｜ 深底拼图 QC ｜ key_frames.py --smooth 0 键控
> 提示词三原则（第一轮实测沉淀）：动作"小摆幅"、明确"无运动残影/无重影/边缘干净"、首尾姿态完全一致。

## 首尾帧策略

| 类型 | 策略 | 适用状态 |
| --- | --- | --- |
| 循环态 | 首帧=末帧（同一关键帧传 kf0/kf1，frame_index 0/-1） | idle / waiting / error / notification / sleeping |
| 一次性态 | 首帧=起始姿态，末帧=定格姿态（两个不同关键帧），播一次回落 idle | celebrate |

## 渲染端配套（第二阶段）
- **图形符号走 DOM 叠加**：`?` / `!` / `Zzz` 由渲染层画在动画上方（CSS 定位角标），不依赖模型画准符号——模型只负责身体动作。
- celebrate 播完一次自动回 idle（主进程已有 4s 定时逻辑，改为按视频实际时长）。

## 排期与成本
每态 ≈ 关键帧 1min + fl2va 6min + 键控 1min ≈ **8 分钟**；6 态串行 ≈ 50 分钟（服务器 GPU0，与 vLLM 切换进行）。
建议批次：P1 idle → P5 sleeping → P3 error（零生图成本）→ P2 waiting → P4 notification → P6 celebrate。

## 验收标准（每态）
1. 深底拼图 12 帧采样无白雾残影（沿用 refcheck 流程）
2. 循环点闭合：首末帧姿态逐像素差分 < 阈值（fl2va 构造保证 + 键控后复核）
3. 角色一致性：汉服配色/发饰/脸型与参考图无漂移
4. 24fps 播放无跳帧，桌宠实机切换状态无闪烁
